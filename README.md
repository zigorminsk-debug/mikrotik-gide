# MikroTik · Учебник Winbox 4 (Android)

Мобильное приложение-учебник по настройке роутеров MikroTik. Меню повторяет структуру
Winbox 4: для каждого пункта и подпункта описан **назначение**, **где применяется** и
**пошаговая инструкция** с окнами Winbox 4, подсветкой элементов и стрелками «куда нажимать».
Дополнительно есть раздел готовых решений для продакшена — от базовой настройки до VLAN,
VPN, балансировки каналов и BGP.

* 13 разделов, **129 статей**, **144 схемы окон** Winbox 4 и терминала
* 18 продакшн-сценариев («Задачи PROD»)
* Полностью офлайн, без сторонних библиотек в APK
* Тёмная/светлая тема, поиск, масштабирование схем под экран телефона

## 1. Структура репозитория

```
app/src/main/java/by/mikrotik/gide/MainActivity.java   # WebView-оболочка (Java, без зависимостей)
app/src/main/assets/www/                               # сам учебник (HTML/CSS/JS, офлайн)
  index.html
  css/app.css
  js/app.js            # навигация, поиск, темы, рендер статей
  js/scene.js          # рендерер «окон Winbox 4» с подсветкой и стрелками
  js/version.js        # номер сборки (перезаписывается в CI)
  js/data/start.js     # раздел «Старт и база»
  js/data/interfaces.js# «Интерфейсы и мосты», «Switch»
  js/data/ip.js        # «IP», «IPv6»
  js/data/net-extra.js # «PPP», «VPN и туннели», «WiFi и CAPsMAN»
  js/data/services.js  # «Routing», «Queues»
  js/data/system.js    # «System», «Tools»
  js/data/tasks.js     # «Задачи PROD»
keystore/              # постоянный ключ подписи (создаётся один раз и коммитится)
scripts/ensure-keystore.sh
.github/workflows/android.yml
```

Приложение — это `WebView` с локальными ассетами: сборка не тянет AndroidX и любые другие
зависимости, поэтому APK весит немного и собирается стабильно.

## 2. Как собрать APK

### Автоматически (GitHub Actions) — основной способ

Любой push в `main` или `arena/**` (а также ручной запуск **Actions → Android APK → Run workflow**)
запускает сборку:

1. выдаётся номер сборки: `versionName = 1.0.<run_number>`, `versionCode = 1000 + run_number`;
2. версия записывается в приложение (`js/version.js`) и видна в меню;
3. APK подписывается постоянным ключом;
4. подпись проверяется через `apksigner verify`;
5. APK загружается артефактом и **прикрепляется к GitHub Release** тегом `build-<номер>`
   **как чистый `.apk`, без zip**.

Скачать: вкладка **Releases** → последняя сборка → `mikrotik-gide-v1.0.<N>.apk`.

> Артефакты во вкладке Actions GitHub всегда отдаёт zip-ом (это особенность самого GitHub),
> поэтому «чистый» APK публикуется именно в Release.

### Локально

```bash
# нужен JDK 17 и Android SDK (platforms;android-34, build-tools;34.0.0)
./gradlew assembleRelease -PappVersionCode=1001 -PappVersionName=1.0.1
# результат: app/build/outputs/apk/release/mikrotik-gide-v1.0.1.apk
```

## 3. Постоянный ключ подписи

Чтобы новая версия ставилась **поверх** установленной, все сборки подписываются одним ключом.

* `keystore/release.jks` + `keystore/keystore.properties` хранятся в репозитории
  (создаются один раз скриптом `scripts/ensure-keystore.sh` при первой сборке).
* **Более безопасный вариант:** добавьте в *Settings → Secrets and variables → Actions*
  секреты `KEYSTORE_BASE64` (файл `.jks` в base64) и `KEYSTORE_PASSWORD` — workflow
  предпочтёт их файлу в репозитории.

⚠️ Если репозиторий публичный, ключ и пароль в нём видны всем: любой сможет подписать
«своё обновление». Для публичного репозитория настоятельно рекомендуется вариант с Secrets
(или приватный репозиторий).

## 4. О содержании и скриншотах

Окна Winbox 4 в приложении — **векторные копии интерфейса RouterOS 7** (та же структура меню,
вкладки, колонки, кнопки, поля), а не растровые скриншоты с реального устройства. Это сделано
осознанно:

* схемы **масштабируются под экран телефона** и остаются читаемыми (растровый скриншот на
  5" экране превращается в кашу);
* приложение остаётся лёгким и полностью офлайн;
* подписи не «плывут» и не содержат артефактов генерации.

Красная рамка + стрелка с номером показывают, куда нажимать, а список под схемой объясняет шаги.

**Как снять собственные скриншоты с настоящего RouterOS:** раздел приложения
«Старт → Лаборатория: виртуальный RouterOS (CHR)» — там пошагово описано развёртывание
CHR в VirtualBox/VMware/Proxmox. Свои снимки можно положить в `assets/www/img/` и подключить
в статьях рядом со схемами.

## 5. Установка на телефон

1. Скачайте APK из Release.
2. Разрешите установку из неизвестных источников для файлового менеджера/браузера.
3. Установите. Обновления ставятся поверх: номер сборки растёт, подпись не меняется.

Минимальная версия Android — 7.0 (API 24), целевая — Android 14 (API 34).
