# MikroTik · Учебник Winbox 4 (Android + Windows)

Приложение-учебник по настройке роутеров MikroTik: **Android (APK)** и **Windows (EXE)**.
Интерфейс общий — один и тот же HTML/JS/CSS зашит в оба приложения, поэтому статьи,
схемы и инструменты всегда совпадают. Меню повторяет структуру
Winbox 4: для каждого пункта и подпункта описан **назначение**, **где применяется** и
**пошаговая инструкция** с окнами Winbox 4, подсветкой элементов и стрелками «куда нажимать».
Дополнительно есть раздел готовых решений для продакшена — от базовой настройки до VLAN,
VPN, балансировки каналов и BGP.

* 15 разделов, **222 статьи**, **265 схем** окон Winbox 4 и терминала, **721 подсказка** со стрелками
* **Размер шрифта**: 90–180 % в восьми ступенях (кнопки A− / A+ в шапке и настройках)
* **Скриншот под каждым шагом**: 1164 шага и 1164 окна — с рамкой на том элементе, о котором говорит шаг
* Если окна для шага нет — показывается меню Winbox с подсвеченным разделом, если шаг про CLI — окно терминала
* Отдельные разделы **WireGuard** и **MPLS** (LDP, VPLS), подробный разбор всех типов VPN: сравнение, плюсы и минусы, настройка
* 30 продакшн-сценариев («Задачи PROD»), у ключевых — блок **«Готовый конфиг»**, копируется одной кнопкой
* **Избранное** (★ в заголовке статьи), **прогресс чтения** и карточка **«Продолжить»** на главной
* **Защита**: чек-лист «Защита от взлома» (56 пунктов по меню), аудит `/export` с оценкой, диагностика по 10 симптомам
* **Инструменты**: мастер конфигурации (готовый `.rsc`), калькулятор подсетей, VLSM-планировщик с CSV, сравнение двух конфигов, самопроверка (**215 вопросов**, тест по разделу) и **экзамен** (30 вопросов, 20 минут), глоссарий и порты, резервная копия данных

## 2. Как собрать APK

### Автоматически (GitHub Actions) — основной способ

Любой push в `main` или `arena/**` (а также ручной запуск **Actions → Android APK → Run workflow**)
запускает сборку:

1. выдаётся номер сборки: `versionName = 1.0.<run_number>`, `versionCode = 1000 + run_number`;
2. версия записывается в приложение (`js/version.js`) и видна в меню;
3. APK подписывается постоянным ключом;
4. подпись проверяется через `apksigner verify`;
5. APK загружается артефактом и **прикрепляется к GitHub Release** тегом `build-<номер>`
   **как чистый `.apk`, без zip**;
6. в этом же прогоне отдельная job на `windows-latest` собирает **`mikrotik-gide-windows-v1.0.<N>.exe`**
   (Go, `go vet` + `go test` перед сборкой) и прикрепляет его к тому же релизу.

Скачать: вкладка **Releases** → последняя сборка → `mikrotik-gide-v1.0.<N>.apk` и
`mikrotik-gide-windows-v1.0.<N>.exe`.

> Правило проекта: любое изменение контента или интерфейса делается один раз —
> в `app/src/main/assets/www` — и попадает в обе версии. Отдельной «версии для Windows»
> с собственным контентом нет и быть не должно.

> Артефакты во вкладке Actions GitHub всегда отдаёт zip-ом (это особенность самого GitHub),
> поэтому «чистый» APK публикуется именно в Release.

### Локально

```bash
# нужен JDK 17 и Android SDK (platforms;android-34, build-tools;34.0.0)
./gradlew assembleRelease -PappVersionCode=1001 -PappVersionName=1.0.1
# результат: app/build/outputs/apk/release/mikrotik-gide-v1.0.1.apk
```

## 3. Постоянный ключ подписи

Чтобы новая версия ставилась **поверх** установленной, все сборки подписываются одним ключом.

* `keystore/release.jks` + `keystore/keystore.properties` хранятся в репозитории
  (создаются один раз скриптом `scripts/check-content.js   # валидатор контента (id, поля, стрелки, ссылки)
scripts/ensure-keystore.sh` при первой сборке).
* **Более безопасный вариант:** добавьте в *Settings → Secrets and variables → Actions*
  секреты `KEYSTORE_BASE64` (файл `.jks` в base64) и `KEYSTORE_PASSWORD` — workflow
  предпочтёт их файлу в репозитории.

⚠️ Если репозиторий публичный, ключ и пароль в нём видны всем: любой сможет подписать
«своё обновление». Для публичного репозитория настоятельно рекомендуется вариант с Secrets
(или приватный репозиторий).

## 4. О содержании и скриншотах

Окна Winbox 4 в приложении — **векторные копии интерфейса RouterOS 7** (та же структура меню,
вкладки, колонки, кнопки, поля), а не растровые скриншоты с реального устройства. Это сделано
осознанно:

* схемы **масштабируются под экран телефона** и остаются читаемыми (растровый скриншот на
  5" экране превращается в кашу);
* приложение остаётся лёгким и полностью офлайн;
* подписи не «плывут» и не содержат артефактов генерации.

Красная рамка + стрелка с номером показывают, куда нажимать, а список под схемой объясняет шаги.

**Как снять собственные скриншоты с настоящего RouterOS:** раздел приложения
«Старт → Лаборатория: виртуальный RouterOS (CHR)» — там пошагово описано развёртывание
CHR в VirtualBox/VMware/Proxmox. Свои снимки можно положить в `assets/www/img/` и подключить
в статьях рядом со схемами.

## 5. Установка на телефон

1. Скачайте APK из Release.
2. Разрешите установку из неизвестных источников для файлового менеджера/браузера.
3. Установите. Обновления ставятся поверх: номер сборки растёт, подпись не меняется.

Минимальная версия Android — 7.0 (API 24), целевая — Android 14 (API 34).

### Ярлыки и виджет

Долгое нажатие на иконку приложения — «Мастер конфигурации», «Защита от взлома»,
«Диагностика», «Самопроверка». Виджет «Продолжить чтение» добавляется на главный экран
через меню рабочего стола: он показывает последнюю открытую статью и процент прогресса.

Приложение также появляется в списке «Открыть с помощью» для текстовых файлов и `.rsc`:
конфигурация сразу попадает в «Аудит конфига».

## 6. Обновления и история версий

* **Установка обновления не выходит из приложения**: APK скачивается во внутренний кэш
  (`cache/update`), показывается прогресс, затем файл передаётся системному
  `PackageInstaller` — открывается штатное окно «Обновить приложение?». После установки
  скачанный APK удаляется (плюс очистка папки обновлений при каждом старте).
  Нужно разрешение `REQUEST_INSTALL_PACKAGES`; если оно выключено, приложение само
  предлагает открыть нужный экран настроек.
* Кнопка **«Проверить обновления»** есть в разделе «Настройки» (иконка шестерёнки в шапке)
  и на экране «О программе». Приложение запрашивает
  `https://api.github.com/repos/zigorminsk-debug/mikrotik-gide/releases/latest`
  и сравнивает версию с установленной. В Android запрос выполняет нативный слой
  (`AndroidBridge.getLatestRelease()`), в браузерном превью — обычный `fetch`.
  Если версия новее, показываются кнопки «Скачать APK» и «Страница релиза».
* **История релизов** живёт в `app/src/main/assets/www/js/data/changelog.js`.
  Новую запись добавляйте **первой** в массив. Для текущей сборки используйте `v: 'auto'` —
  номер подставится из `window.APP_VERSION` автоматически, поэтому не нужно знать
  номер будущего запуска CI.

```js
{
  v: 'auto',                     // или конкретный номер, например '1.0.12'
  date: '2026-11-03',
  title: 'Короткое название релиза',
  items: ['Что изменилось — пункт 1', 'Пункт 2']
}
```

* **Размер шрифта** — 5 ступеней (90…130 %), применяется через `data-fs` на `<html>`,
  выбор хранится в localStorage.
* **Увеличение схем** — `Scene.openZoom()`: копия схемы в полноэкранном слое,
  масштаб 45…220 %, вписать по ширине, прокрутка; закрытие по ✕ или Esc.

| **Курс за 7 дней** | программа по дням: 35 статей, цели, практика и команды проверки, прогресс и даты от старта курса |
| **Порты моделей** | 5 моделей: какие порты WAN/LAN, где PoE и SFP, как называются интерфейсы в RouterOS |
| **Данные и резервная копия** | экспорт и импорт заметок, избранного, прогресса, чек-листов и ответов мастера в JSON; выгрузка всей библиотеки в HTML
| **Поиск** | по всем статьям, шагам, командам и конфигам: подсветка совпадений, история запросов, счётчик результатов |

В настройках — **«Библиотека для печати»**: одна кнопка сохраняет все статьи в
самодостаточный HTML-файл `mikrotik-gide-library-ГГГГ-ММ-ДД.html` (стили внутри,
открывается в любом браузере, печатается и читается офлайн).

**Навигация.** В шапке есть кнопка **«Назад»**: она возвращает в предыдущий раздел и
восстанавливает позицию прокрутки (запоминается в `sessionStorage` по каждому hash),
поэтому из статьи, карточки примера или шпаргалки можно вернуться ровно туда, где вы
остановились, а не наверх списка. На главной кнопка скрыта.

Плюс в статьях: **заметки** (хранятся на устройстве) и **режим «на объекте»** — чек-лист
шагов с галочками, прогрессом и таймером.

## 9. Контент-пак (статьи без обновления APK)

`content-pack/pack.json` собирается скриптом `scripts/build-pack.js` в `content-pack.json`
и публикуется в каждом релизе. Приложение скачивает его по адресу
`releases/latest/download/content-pack.json` (кнопка «Проверить обновления контента»
в настройках) и добавляет статьи в меню, поиск и прогресс — переустанавливать APK не нужно.

```bash
node scripts/build-pack.js      # проверка и сборка content-pack.json
```

Формат: `{ version, title, groups: [{ id, name, ic, items: [статья…] }] }` — те же поля,
что у обычных статей. Валидация: `scripts/check-content.js` проверяет и основной контент, и пак.

## 11. Windows-версия (Go, один EXE)

| | Android | Windows |
|---|---|---|
| Файл | `mikrotik-gide-v1.0.N.apk` | `mikrotik-gide-windows-v1.0.N.exe` |
| Интерфейс | WebView + общий `www` | Edge/Chromium в режиме приложения + тот же `www` |
| Обновление | APK поверх (подпись постоянная) | кнопка в приложении: «О программе» → «Проверить обновление» |
| Данные | SharedPreferences | `%LOCALAPPDATA%\MikroTikGide` (настройки, профиль окна, лог) |

**Один источник контента.** Android и Windows берут статьи из `app/src/main/assets/www`.
Windows-сборка зашивает каталог в EXE через `//go:embed` (см. `assets.go`), поэтому любая
правка статьи, схемы, стиля или инструмента автоматически появляется в обеих версиях.

Структура:

```
assets.go                 встраивание app/src/main/assets/www в бинарник
go.mod                    модуль Go (без внешних зависимостей)
windows/main.go           запуск сервера, окно, флаги, каталог данных
windows/server.go         локальный HTTP-сервер, /api/version, /api/update/*
windows/updater.go        GitHub Releases, проверка версии, скачивание, замена EXE
windows/ui.go             окно Edge/Chrome в режиме приложения
windows/desktop.js        мост обновления в общем интерфейсе
windows/icon.ico          значок EXE и окна (256…16 px)
windows/icon.png          исходник значка 512×512 с прозрачными углами
windows/*_test.go         тесты (go test ./...)
```

Сборка из исходников:

```bash
go build -trimpath -ldflags "-H windowsgui -s -w -X main.version=1.0.N -X main.buildNo=N" -o mikrotik-gide.exe ./windows
```

Как работает:

* локальный сервер на `127.0.0.1:47800` (если порт занят — следующий свободный), окно Edge/Chrome
  в режиме приложения с отдельным профилем; если браузера нет — открывается системный браузер;
* флаги: `-port`, `-browser`, `-no-window`, `-version`;
* обновление: приложение спрашивает GitHub Releases, скачивает `.exe`, проверяет размер и SHA-256,
  подменяет файл, закрывает окно и запускает новую версию; прошлый файл остаётся как `.exe.old`
  до следующего старта;
* логи — `%LOCALAPPDATA%\MikroTikGide\app.log`.

Значок: `windows/icon.ico` (размеры 256, 128, 64, 48, 32, 16) встраивается в EXE генератором
ресурсов `rsrc` на шаге «Иконка приложения» в CI — поэтому в Проводнике, на панели задач
и в ярлыке виден роутер с зелёными дугами Wi-Fi. В Android и в браузере используется тот же
рисунок: `app/src/main/assets/www/img/{favicon.ico,icon-32.png,icon-180.png}` (иконка вкладки
и `apple-touch-icon`).

GitHub Actions собирает APK и EXE в одном прогоне (`build-N`), оба файла попадают в один релиз.
