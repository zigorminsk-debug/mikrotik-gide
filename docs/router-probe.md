# Опрос роутера из программы: версия, прошивка, плата

Задача: конструктор скрипта должен собирать конфиг **под конкретный роутер**, а не «под
RouterOS 7 вообще». Версия 6.x и 7.x, пакет `wireless` и пакет `wifi`, разные имена портов
(`ether1…ether5` у RB951G против `ether1…ether10` у RB4011) — всё это меняет команды.

## Где что лежит

| Файл | Что делает |
| --- | --- |
| `windows/rosapi.go` | Клиент протокола MikroTik API (8728/8729) на стандартной библиотеке Go: слова с префиксом длины, оба варианта входа (6.43+ с логином/паролем и старый challenge-вход), сбор «паспорта» роутера. |
| `windows/rosrest.go` | Второй транспорт — REST RouterOS 7 поверх HTTPS (`/rest/...`), с basic-auth и самоподписанным сертификатом. |
| `windows/discover.go` | Поиск роутеров без логина: MNDP (UDP 5678) плюс перебор портов 8728/8291 только в подсетях реальных адаптеров. |
| `windows/rosdiag.go` | Диагностика подключения: виды ошибок (`connect`/`timeout`/`auth`/`permission`/`protocol`), проверка портов без логина, подсказки по политикам. |
| `windows/devices.go` | Список опрошенных роутеров в `%LOCALAPPDATA%\MikroTikGide\routers.json`. Пароль не сохраняется. |
| `windows/roshttp.go` | HTTP-мостик для страницы учебника: `/api/router/probe`, `/api/router/check`, `/api/router/discover`, `/api/router/saved`. |
| `app/src/main/assets/www/js/rosprobe.js` | Профиль версии RouterOS, поиск модели по плате, поля мастера под роутер, вызовы мостика. |
| `app/src/main/assets/www/js/wizard.js` | Использует паспорт: шапка «Цель: …», раздел проверки версии, ветка 6.x (wireless, без WireGuard). |
| `app/src/main/assets/www/js/app.js` | Карточка «Версия роутера» в мастере и вся логика кнопок. |

## Почему опрос делает Go-сервер, а не страница

Страница — обычный HTML в WebView/браузере, из JavaScript нельзя открыть TCP к порту 8728.
Поэтому соединение с роутером держит Go-часть (она уже работает как локальный сервер для
обновлений), а страница получает готовый JSON. Заодно пароль не покидает локальный процесс.

Порядок попыток при опросе:

1. **REST 443** (`https://адрес/rest/system/resource`) — самый простой путь, но требует
   включённого `www-ssl` с сертификатом.
2. **API 8728** — `/ip service enable api`; работает и в 6.x, и в 7.x.
3. **API-SSL 8729** — если открыт только защищённый API.

Если все три закрыты, программа честно пишет, что включить на роутере, и показывает причину
по каждой попытке.

## Почему вход не проходит при верном пароле

Раньше любая неудача превращалась в «роутер отклонил логин или пароль» — и человек
искал ошибку в пароле, хотя проблема была в другом. Теперь каждая попытка описывается
отдельно (`windows/rosdiag.go`), а страница показывает таблицу «путь / порт / что вышло»
и подсказки.

| Вид (`kind`) | Что произошло | Что делать |
| --- | --- | --- |
| `connect` | TCP не открылся: сервис выключен или режет firewall | включить сервис (`/ip service enable api`) |
| `timeout` | нет ответа за отведённое время | проверить адрес и сегмент сети |
| `auth` | роутер сам ответил «неверный логин или пароль» | сверить с Winbox, проверить 2FA |
| `permission` | вход принят, но прав на API нет | политика `api` (для REST — `rest-api`) |
| `protocol` | ответил не RouterOS | адрес чужой — взять из поиска или вписать вручную |

Порядок выбора итогового сообщения: `auth`/`permission` важнее `connect` — иначе
человек идёт включать сервис, который уже включён.

Настоящие причины, которые чаще всего выглядят как «неверный пароль»:

1. **Нет политики `api`** у группы: `/user group print detail`. Для REST нужна ещё
   `rest-api`.
2. **Включён 2FA/TOTP** у пользователя — вход по API невозможен, только Winbox/веб.
3. Сервис выключен: `/ip service print` → у `api` флаг `X`.
4. В `/ip service` в колонке **Address** ограничен доступ чужой подсетью.
5. Лишний пробел или другая раскладка в пароле — подсказка предлагает сверить с Winbox.
6. **Конфиг «защиты» из мастера** выключает `api` и `www-ssl`: после его применения
   опрос не работает до повторного включения сервисов.

### Кнопка «Проверить доступность»

`GET /api/router/check?address=…` → `windows/rosdiag.go:checkRouterPorts`. Проверяет
TCP-соединение на 8291 (Winbox), 8728 (API), 8729 (API-SSL), 443 (REST), 80, 22 —
**без логина и пароля**, поэтому кнопку можно нажимать до ввода пароля. Ответ:

```json
{"ok":true,"address":"192.168.88.1","open":[8291],
 "ports":[{"port":8728,"label":"API","open":false,"detail":"закрыт — включите /ip service enable api"}]}
```

Если открыт только 8291 — Winbox работает, а опрос нет: это самый частый случай.

### Поиск в сети: почему раньше были «чужие» адреса

Две причины, обе исправлены в `windows/discover.go`:

* сканировались **все** приватные /24 всех адаптеров, включая Hyper-V
  (`172.17–31.x`), WSL, Docker, VirtualBox (`192.168.56.x`), VPN;
* адрес брался из «подобранного» разбора MNDP, то есть иногда — из случайных байт.

Сейчас `usableLocalAddr()` отбрасывает виртуальные адаптеры (по имени) и служебные
диапазоны (по адресу), адрес берётся из **источника UDP-пакета**, а MNDP разбирается
строго: тип 1–12, длина поля в пределах пакета, MAC ровно 6 байт, IPv4 ровно 4 и не
`0.0.0.0`. Не прошло проверку — пакет выброшен. Страница делит результат на
«В вашей сети» и свёрнутое «Ещё в сети» по полю `sameNet`.

`GET /api/router/discover?address=192.168.88.1` — подсеть указанного адреса
сканируется первой.

## Что именно забирается

```
/system resource        version, board-name, architecture-name, platform, uptime
/system routerboard     current-firmware, upgrade-firmware, model, serial-number
/system identity        name
/system package         routeros, wireless, wifi-qcom, container …
/system license         nlevel (6.x)
/ip service             включённые сервисы и их address
/interface              порты ether
/interface wireless     wlan1, wlan2  → пакет wireless (legacy)
/interface wifi         wifi1, wifi2  → пакет wifi
```

Из этого собирается «паспорт»: версия, мажор/минор, плата, модель, архитектура, прошивка
RouterBOOT (текущая и доступная для обновления), серийник, пакеты, порты, радиоинтерфейсы,
диапазон 5 ГГц, сервисы, лицензия, uptime.

## Как это влияет на конфиг

* **Модель и порты.** Плата `RB951G-2HnD` → модель `rb951` (WAN `ether1`, LAN `ether2-5`),
  `RB4011iGS+` → `rb4011` (LAN до `ether10`). Имена портов из `/interface` тоже показываются
  в отчёте — по ним видно, если на роутере переименованы интерфейсы.
* **Пакет Wi-Fi.** `wireless` → `/interface wireless security-profiles`, `wlan1/wlan2`.
  `wifi` (7.13+) → `/interface wifi security|configuration|datapath`, `wifi1/wifi2`.
* **Версия.** В шапку пишется «Цель: RouterOS 7.24.6 · RB951G-2HnD · прошивка RouterBOOT
  6.49.13», а в начало скрипта — раздел проверки:

  ```rsc
  :local rosVer [/system resource get version]
  :if ([:pick $rosVer 0 1] != "7") do={
    :put ("ВНИМАНИЕ! На роутере " . $rosVer . ", конфиг собран под 7.24.6")
  }
  ```

* **6.x.** Скрипт собирается для `wireless`, WireGuard не создаётся (в 6.x его нет),
  `service-ports` не используется — и всё это проговаривается в комментариях.
* **Прошивка RouterBOOT.** Если `upgrade-firmware` отличается от `current-firmware`,
  в отчёте видно `6.47.10 → 6.49.13` — перед обновлением RouterOS прошивку как раз и
  поднимают (`/system routerboard upgrade`).

## Применение конфига прямо из программы

Кнопки в блоке «Готовый конфиг» мастера (и на странице «Мой роутер»):

* **«Что изменится на роутере»** — сравнение с текущим состоянием: каждая строка
  помечается как `создать`, `уже есть`, `изменить`, `скрипт` или `чтение`.
  Ключ сравнения — `comment` → `name` → `address` → `dst-address` → `interface`/`chain`
  (то же, по чему мастер делает идемпотентные проверки).
* **«Применить на роутере»** — построчная отправка через API с отчётом по каждой строке:
  `ok` / `exists` («уже настроено») / `error` (с текстом от роутера) / `script`.

Как разбирается конфиг (`windows/rosapply.go`):

| Строка конфига | Что делает программа |
| --- | --- |
| `/ip address add address=… interface=…` | разбирает на путь + действие + аргументы и отправляет как `/ip address/add =address=…` |
| `:do {команда} on-error={}` | снимает обёртку, отправляет команду, ошибку считает нормой |
| `:if ([:len [...]] = 0) do={команда}` | то же: команда уже есть — это нормально |
| `:local`, `:put`, прочие выражения | складывает в один временный скрипт `mtg-wizard-HHMMSS`, запускает и удаляет |
| `print`, `export`, `monitor`, `get`, `find` | не отправляет (только чтение) |
| `# комментарии` | пропускает |

Важно: **применение возможно только через API (8728 или api-ssl 8729)** — REST для
записи не используется. Если API закрыт, программа прямо об этом скажет и подскажет команду.

## Применение конфига: правила разбора (важно при правках)

`windows/rosapply.go` отправляет `.rsc` построчно. Правила, которые нельзя
нарушать — на них уже наступали:

| Строка конфига | Что делает программа |
| --- | --- |
| `/ip address add address=… interface=…` | путь + аргументы, отправляется как `/ip/address/add` |
| `/interface wireless set wlan1 ssid=… security-profile=…` | позиционное слово — это `numbers=wlan1`. **Раньше оно терялось, если рядом были аргументы** — отсюда «Wi-Fi не меняется» |
| `/interface wireless set [find default-name=wlan1] …`, `place-before=[…]` | выражения `[ … ]` в API не существуют, поэтому строка уходит на роутер **целиком, скриптом** — с той же семантикой, что при `/import` |
| `:do {команда} on-error={}` | команда отправляется, а её отказ показывается как **«не применилось»** с текстом роутера. Раньше это выглядело как «уже есть» — и применение казалось успешным |
| `:if ([:len [/ip … find]] = 0) do={команда}` | снимается обёртка, команда отправляется; «already have» считается нормой |
| `:local`, `:put`, прочие выражения | собираются в скрипт и выполняются пачками **в исходном порядке** |
| `/ip service disable … api …` | выполняется **последней**: иначе программа теряет связь с роутером на середине конфига; в отчёте — предупреждение, как вернуть доступ |
| `print`, `export`, `monitor`, `find` | только чтение, не отправляются |

После всех строк программа перечитывает `/ip address`, `/interface wireless`
и `/interface wifi` и добавляет в отчёт строки со статусом `state` — блок
«Сейчас на роутере». Это единственный способ показать пользователю правду:
отчёт «выполнено» без проверки уже один раз вводил в заблуждение.

### Смена LAN-подсети в мастере

Когда в мастере выбрана не заводская подсеть (не `192.168.88.0/24`), генератор
добавляет к обычным строкам:

```rsc
/ip address add address=192.168.90.1/24 interface=bridge-lan
:if ([:len [/ip address find where address="192.168.90.1/24"]] > 0) do={
  :do {/ip address remove [/ip address find where address="192.168.88.1/24"]} on-error={}
}
:do {/ip dhcp-server set [find interface=bridge-lan] address-pool=lan-pool} on-error={}
:do {/ip dhcp-server network remove [/ip dhcp-server network find where address="192.168.88.0/24"]} on-error={}
:do {/ip pool remove [/ip pool find where name="default-dhcp"]} on-error={}
```

Заводской адрес снимается **только если новый уже стоит** — иначе легко
остаться без доступа к роутеру. Существующий DHCP-сервер переводится на новый
пул (`set`), а не дублируется (`add` на занятом интерфейсе роутер отклонит).

## Снимок состояния и обновления

* **«Прочитать состояние»** — читает 33 меню (`/ip address`, `/ip route`, `/ip firewall filter`,
  `/interface bridge*`, `/interface wireless*`, `/interface wifi*`, `/ip service`, `/system scheduler`
  и др.), сохраняет в `%LOCALAPPDATA%\MikroTikGide\snapshot-<адрес>.json` и показывает
  сводку по разделам. Этот снимок использует и «что изменится».
* **«Проверить обновления»** — `/system package update check-for-updates` + `print` и
  `/system routerboard print`: показывает установленный и доступный RouterOS, текущую и
  доступную прошивку RouterBOOT.
* **Обновить RouterOS / прошивку / Перезагрузить** — только по явному подтверждению;
  для `check-for-updates` таймаут ответа поднят до 45 секунд (роутер ходит в интернет сам).

## Страница «Мой роутер»

`#/router` (Инструменты → Мой роутер): подключение, список сохранённых роутеров с версией и
прошивкой, «Прочитать состояние», «Проверить обновления». Кнопка «В мастер» подставляет
паспорт роутера (модель, порты, пакет Wi-Fi, версия) в конструктор.

## Ограничения

* **Android.** Автоопроса нет: WebView не умеет TCP к 8728, а REST не отдаёт CORS-заголовки.
  Поля «RouterOS / Плата / Прошивка» остаются — их заполняют вручную, логика сборки та же.
* **www-ssl по умолчанию выключен** нашей же защитой (`/ip service disable www-ssl`). Для
  REST-опроса его нужно включать осознанно: `/ip service enable www-ssl`.
* **Самоподписанный сертификат** принимается без проверки — соединение идёт внутри локальной
  сети, а проверять на роутере нечего. Это отмечено в коде.
* **Пароль не сохраняется.** `routers.json` содержит только адрес, имя, версию, плату и
  прошивку.

## Что сделано и что осталось

Сделано: опрос версии/прошивки, поиск в сети, паспорта, план изменений, применение конфига
построчно, снимок состояния, проверка и установка обновлений RouterOS/прошивки, страница
«Мой роутер».

Перед первой командой программа делает бэкап на самом роутере:
`/system backup save name=before-apply-ГГГГММДД-ЧЧММ dont-encrypt=yes`. Имя бэкапа видно
в отчёте — если что-то пошло не так, конфиг возвращается через **Files → Restore**.
Полный откат одной кнопкой пока не сделан: для него нужен `/export`, который по API
не отдаётся в текст (его пишут в файл на роутере).

Осталось (по возрастанию пользы):

1. **Откат одной кнопкой** — читать `/export` через файл на роутере и хранить снимок в
   программе, чтобы возвращаться к нему без Winbox.
2. **Проверка синтаксиса без применения**: отправлять команды в режиме «примерки» через
   `/system script` + `:parse`, чтобы ловить опечатки до записи.
3. **Живой прогресс**: показывать ответ роутера по мере выполнения (сейчас — итоговый список).
4. **Несколько профилей на роутер** (например, «до/после смены провайдера»).

## Как проверить руками

```bash
# REST (нужен включённый www-ssl)
curl -k -u admin:пароль https://192.168.88.1/rest/system/resource
curl -k -u admin:пароль https://192.168.88.1/rest/system/routerboard

# в терминале роутера
/system resource print
/system routerboard print
/interface wireless print
/ip service print
```

В приложении: **Инструменты → Мастер конфигурации → Версия роутера**.
