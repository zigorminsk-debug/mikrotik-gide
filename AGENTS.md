# AGENTS.md — как продолжить работу над проектом

Файл для того, кто откроет репозиторий впервые (человек или агент) и должен
что-то поправить без археологии в 90 коммитах. Читается за 10 минут.

Связанные документы: `README.md` (что умеет программа), `docs/coverage.md`
(покрытие меню RouterOS), `docs/router-probe.md` (подключение к живому
роутеру — самое хрупкое место).

---

## 1. Что это

Учебник по настройке MikroTik. **Две оболочки, одна страница:**

| Оболочка | Технологии | Как собирается |
| --- | --- | --- |
| Android | Java + WebView, всё офлайн | Gradle → APK, CI `android.yml` |
| Windows | Go + локальный HTTP-сервер, окно на WebView2/Chromium | `go build` → один `.exe`, CI `android.yml` (тот же job) |

Страница лежит в **`app/src/main/assets/www/`** и вшивается в оба приложения
через `go:embed` (`assets.go`) — поэтому **любая правка интерфейса сразу
относится к обеим версиям**. Правки только в одну версию делать нельзя, кроме
случая, когда функция физически невозможна (например, опрос роутера по TCP
из WebView Android).

Правило проекта: **всё, что видит пользователь, — по-русски**; текст без
сокращений в стиле «роутер», «мастер», «снимок» (а не `probe`, `wizard`,
`snapshot`).

## 3. Локальный запуск и сборка

```bash
# Страница в браузере (быстро посмотреть интерфейс)
python3 -m http.server -d app/src/main/assets/www 8000
#   → http://localhost:8000   (без /api/... , опрос роутера работать не будет)

# Go-часть (Windows-версия):
cd windows && go vet ./... && go test ./... && go build -o dist/mtg.exe .
#   Go в песочнице Arena не установлен — проверяйте через CI (go-check.yml)
#   или локально. Форматирование без Go: npx @wasm-fmt/gofmt

# Android (нужен Android SDK):
./gradlew assembleDebug
```

Сборки и релизы делает CI. Версия = номер прогона (`build-N`);
`js/version.js` и `versionName` подставляются в workflow, руками не правятся.

## 4. Где что менять (частые задачи)

| Задача | Файлы |
| --- | --- |
| Текст статьи, шаг, схема шага | `js/data/*.js` (см. формат ниже) |
| Новый экран/инструмент | `js/app.js`: `VIEWS`/`TOOL_TITLES`, функция `*View()`, `bind*()`, обработчик в `route()` |
| Новая настройка | `store`-ключи в `app.js` + строка в `settingsView()` |
| Вопросы самопроверки | `js/data/quiz.js`, `js/data/quiz2.js` |
| Модели и ТТХ | `js/data/models.js` (`MODEL_SPECS`) — только официальные цифры |
| Подключение к роутеру | `js/rosprobe.js` + `windows/ros{api,rest,diag,http}.go` + `docs/router-probe.md` |
| Поиск роутеров в сети | `windows/discover.go` (правила фильтра — `usableLocalAddr`) |
| Снимки окон Winbox 4 | `.github/workflows/winbox-shots.yml` → артефакты → `docs/shots/`, `js/data/win4.js` |
| Обновление из программы | `windows/updater.go` + `js/app.js` (блок обновлений) |

### Формат статьи (`js/data/*.js`)

```js
{
  id: 'ip-firewall-filter',      // уникальный, используется в ссылке #/id
  cat: 'ip',                     // группа меню (см. GROUPS)
  title: 'IP → Firewall → Filter',
  purpose: '…',                  // назначение
  where: '…',                    // где применяется
  steps: [
    { t: 'Что делать', win: 'win-ip-firewall', hl: '…', cmd: '…' }
  ],
  config: '…'                    // необязательный готовый .rsc
}
```

`win` — идентификатор схемы (см. `js/data/shots.js` / `WIN4_SHOTS`),
`cmd` — команда RouterOS (подсвечивается `hl.js`).

## 5. Проверки перед коммитом

```bash
node scripts/check-content.js      # контент: id, категории, шаги, схемы
node scripts/ui-check.js           # интерфейс в jsdom (нужен: npm i --no-save jsdom)
cd windows && go vet ./... && go test ./...
```

`scripts/ui-check.js` поднимает `index.html` в jsdom, подключает все скрипты
страницы, подменяет `fetch` и нажимает кнопки. Сейчас он покрывает страницу
«Мой роутер»: карточку подключения, памятку про политики API, разбор
неудачного опроса (таблица попыток), «Проверить доступность» и поиск в сети
(разделение «В вашей сети» / «Ещё в сети»). Добавляя экран — добавляйте
проверку: CI собирает APK, но поведение кнопок не проверяет.

Go-тесты лежат рядом с кодом (`windows/*_test.go`). Ключевые:
`parseMNDP` (строгий разбор MNDP и отбраковка мусора), `usableLocalAddr`
(фильтр виртуальных подсетей), `classifyTrap` (пароль ≠ нет прав),
`newProbeError` (приоритет вида ошибки), разбор `.rsc` в `rosapply_test.go`.

## 6. Подключение к роутеру: как устроено и где грабли

Цепочка: `js/rosprobe.js` → `POST /api/router/probe` → `windows/roshttp.go`
→ `probeRouter()` в `rosapi.go` → по очереди REST 443 → API 8728 → API-SSL 8729.

### Каждый отказ классифицируется (`windows/rosdiag.go`)

| Вид | Что значит | Что показываем |
| --- | --- | --- |
| `connect` | порт закрыт / не пускает | включить сервис, проверить адрес |
| `timeout` | нет ответа | другой сегмент сети, firewall |
| `auth` | роутер сам отклонил логин/пароль | текст роутера дословно + 2FA + политики |
| `permission` | вход принят, но нет прав на API | политика `api` / `rest-api` |
| `protocol` | ответил не RouterOS | адрес из поиска — чужой |

**Никогда не возвращайте короткое «отклонил логин или пароль» без разбора:**
именно это и была жалоба пользователя — пароль верный, а сообщение врёт.
Текст роутера (`invalid user name or password (6)`) сохраняется в `detail`
каждой попытки и виден в таблице под сообщением.

### Реальные причины отказа при верном пароле

1. У группы пользователя нет политики **`api`** (`/user group print detail`).
   Для REST нужна ещё **`rest-api`**.
2. У пользователя включён **2FA/TOTP** — вход по API невозможен.
3. Сервис выключен: `/ip service print` → флаг `X` у `api` (или
   `/ip service enable api`).
4. В `/ip service` в колонке **Address** стоит чужая подсеть.
5. Пароль «верный» по мнению пользователя, но с лишним пробелом/в другой
   раскладке — поэтому подсказка предлагает сверить с Winbox.
6. **Собственный конфиг «защиты»** из мастера выключает `api` и `www-ssl` —
   после его применения опрос не работает, пока сервисы не включат снова.

### Поиск в сети (`windows/discover.go`)

Жалоба «находит непонятные IP не из этой сети» имела две причины, обе
исправлены. **Не возвращайте старое поведение:**

* Раньше сканировались все приватные /24 всех адаптеров: Hyper-V
  (`172.17–31.x`), WSL, Docker (`172.x`), VirtualBox (`192.168.56.x`), VPN.
  Теперь `usableLocalAddr()` отбрасывает виртуальные адаптеры (по имени) и
  служебные диапазоны (по адресу), а `usableLocalNets()` оставляет /24
  реальных адаптеров.
* Раньше адрес брался из «эвристически» разобранного MNDP (случайные байты
  выдавались за IP). Теперь адрес — **источник UDP-пакета**
  (`ReadFromUDP`), а TLV разбирается строго: тип 1–12, длина совпадает,
  MAC ровно 6 байт, IPv4 ровно 4 и не `0.0.0.0`. Пакет не прошёл проверку —
  выбрасывается целиком.

Интерфейс показывает «В вашей сети» и свёрнутое «Ещё в сети» (`sameNet`),
у каждой строки — плата, версия, MAC и источник (`MNDP` или номер порта).

### Как проверить руками

```powershell
Test-NetConnection 192.168.88.1 -Port 8728
curl.exe -k -u admin:ПАРОЛЬ https://192.168.88.1/rest/system/resource
```

На роутере: `/ip service print`, `/user print detail`, `/user group print detail`.
Журнал Windows-версии: `%LOCALAPPDATA%\MikroTikGide\app.log` — там каждая
попытка подключения и каждый найденный адрес.

## 7. CI

| Workflow | Что делает | Триггер |
| --- | --- | --- |
| `android.yml` | vet + тесты Go, сборка Windows `.exe`, сборка APK, подпись, релиз `build-N` с контент-паком | push, PR, ручной запуск |
| `go-check.yml` | быстрый `go vet`/`go test` | push, PR |
| `winbox-shots.yml` | поднимает CHR в QEMU и снимает окна Winbox 4 | только по файлу `ci/winbox-shots.trigger` |

**Грабли CI (проверено на практике):**

* CHR не грузится с `-cpu qemu64`/`Haswell` — только **`-cpu max`**.
* Разведка подменю по заголовку окна не работает: Winbox не меняет `title`.
  Координаты только со снимков `tree-*.png`, шаг по дереву ≈ **23 px**.
* Job зелёный ≠ снимки правильные: workflow не валит себя за «пустой» кадр.
  После прогона обязательно смотреть артефакты глазами.
* Логи прогона: `gh run view --log` часто отдаёт `EOF`, а
  `gh api .../actions/runs/<id>/jobs` работает.
* Голый `git push` отбивается: workflow коммитит снимки. Всегда
  `git fetch && git pull --rebase`.

## 8. Соглашения

* **Комментарии по-русски и по делу.** В начале каждого нетривиального файла —
  шапка: что делает, почему так, где грабли. Внутри — объяснение решений, а
  не пересказ кода.
* Заголовки-разделители: `/* ---- раздел ---- */`.
* **Ноль сторонних зависимостей** в APK и в Windows-сборке: только стандартная
  библиотека Go и обычный JS. jsdom — только для тестов (`npm i --no-save`,
  `node_modules/` в `.gitignore`).
* Пароль роутера не сохраняется никогда; `routers.json` — адрес, логин,
  паспорт.
* Числа в интерфейсе — из `MODEL_SPECS` и официальных страниц MikroTik, не
  «по памяти».
* Не ломать поведение «Назад» (возврат к той же прокрутке) и размер шрифта
  (8 ступеней, `FS_STEPS`).

## 9. Что осталось в плане

1. **Сравнение моделей таблицей** (сейчас — матрица в `modelsView()`):
   выбрать 2–4 модели и показать общие/различающиеся ТТХ столбцами.
2. **Чек-лист выезда с таймером и отчётом** (основа есть: `runView()` /
   `bindRun()` — режим «на объекте»): таймер по шагам, итоговый отчёт в файл.
3. **Откат конфигурации одной кнопкой** (см. `docs/router-probe.md`):
   нужен `/export` через файл на роутере.

## 10. Быстрый чек-лист для новой сессии

```bash
git pull --rebase                # CI мог закоммитить снимки
node scripts/check-content.js
node scripts/ui-check.js         # npm i --no-save jsdom, если ещё нет
cd windows && go vet ./... && go test ./...
```

Дальше — §4 (где менять) и §6 (если речь про подключение к роутеру).
Изменения должны попадать в **обе** версии: страница общая, а Go-часть
собирается вместе с APK в одном workflow.
